# Виджеты рабочего стола Meshex

Android и iOS предоставляют пять отдельных виджетов: Mesh Status, Node Tracker,
Messages, Node Map и Trace Route. Палитра совпадает с `lib/ui/tokens.dart`:
синий `#227DF3`, фиолетовый `#8848DB`, розовый `#CF3E83`.

## Использование

Один раз откройте Meshex и подключитесь к ноде, чтобы заполнить данные.

- Android: удержание на рабочем столе → Виджеты → Meshex. После добавления
  виджет можно растягивать. Компоновка и число сообщений зависят от размера.
  Для Node Tracker выберите ноду при добавлении; на поддерживаемых лаунчерах
  её можно изменить через настройку уже размещённого виджета.
- iOS 17+: удержание на домашнем экране → Добавить виджет → Meshex.
  Mesh Status, Node Map и Trace Route доступны в трёх размерах, Node Tracker —
  в малом и среднем, Messages — в среднем и большом. Ноду выбирают через
  «Изменить виджет». Несколько экземпляров могут следить за разными нодами.

Нажатие открывает соответствующий раздел приложения; отдельное сообщение
открывает его переписку, трассировка — конкретную запись истории.

Виджеты отображают снимок данных, а не устанавливают собственное соединение
с радио. Обновление зависит от работы приложения в фоне и планировщика ОС.
Подпись показывает время снимка; после двух часов он помечается устаревшим.
При потере связи статус скрывает текущие метрики радио. Трассировка сохраняет
собственное время получения. Для карт нужны загруженные тайлы: используется
существующий дисковый кэш OSM; офлайн недостающие тайлы не выдумываются.
Старая карта не переносится в снимок другой сети. На карте сохраняется
атрибуция OpenStreetMap.

В Messages отображаются последние пять сообщений и общий счётчик непрочитанных.
Игнорируемые ноды, скрытые каналы и скрытые фильтром сообщения не выводятся.
Текст виден на рабочем столе, поэтому добавляйте этот виджет с учётом этого.

## Устройство

- `lib/features/home_widgets/`: ограниченный JSON-контракт, подписки Riverpod,
  подготовка карт. Обновления объединяются, не чаще одного цикла за 30 секунд;
  карты готовятся только для размещённых виджетов соответствующего вида.
- `packages/meshex_widgets/`: локальный Flutter-плагин без внешних зависимостей.
  Android использует AppWidgetProvider/RemoteViews, приватные preferences и
  PNG. Ноды выбираются в отдельной configuration activity, выбор привязан к
  appWidgetId. Системное обновление раз в 30 минут проверяет устаревание,
  не создавая фонового Flutter-движка. Ресурсы поддерживают светлую/тёмную тему.
- `native/ios_widgets/`: WidgetKit и AppIntent выбора ноды. Снимки и карты
  читаются из App Group `group.ru.meshex.app`; timeline учитывает границу
  устаревания. URL-схема `meshex:///…` открывает маршруты GoRouter.
- `tool/install_ios_widgets.rb`: идемпотентно добавляет extension target,
  embedding, URL scheme и entitlements после `flutter create`. Вызывается
  из `tool/patch_platforms.py`; нужен Ruby с gem `xcodeproj` (есть у CocoaPods).
  Плагин поддерживает Swift Package Manager и CocoaPods.

Папки платформ игнорируются git. Изменения нужно делать в указанных исходниках,
затем запускать `python3 tool/patch_platforms.py`.

## Сборка и проверка

```sh
flutter pub get
python3 tool/patch_platforms.py
flutter analyze
flutter test
flutter build apk --debug
flutter build ios --simulator --no-codesign
```

Для подписанной iOS-сборки у Runner и MeshexWidgets должна быть одна команда
разработчика, а профили обоих bundle ID (`ru.meshex.app` и
`ru.meshex.app.widgets`) должны разрешать App Group `group.ru.meshex.app`.
Регистрация App Group в Apple Developer — отдельная настройка учётной записи.
Неподписанная CI-сборка сама её не создаёт. Расширение наследует версии из
Flutter/Generated.xcconfig, включая `--build-name` и `--build-number`.

Перед публикацией проверить оба оформления, крупный системный шрифт, все
размеры, несколько Node Tracker, отсутствие данных, отключение радио,
перезапуск приложения/лаунчера и переход между базами нод на устройствах.
