# Локализация Meshex

Интерфейс использует Flutter `gen-l10n`: `app_ru.arb` — шаблон, `app_en.arb` —
английский перевод. Язык системы используется по умолчанию; неподдерживаемые
языки дают русский интерфейс. Выбор пользователя хранится в общей базе приложения
(`app.locale`) и не зависит от подключённой ноды.

## Обновить тексты

1. Добавить сообщение с одним и тем же ключом в ARB каждого языка. Для новых
   экранов выбирать короткие смысловые ключи, как `compassTitle`.
2. Для параметров описать `placeholders` в шаблоне. Не соединять переведённые
   фразы с именами, сообщениями или другими пользовательскими данными заранее.
3. Выполнить `flutter gen-l10n`. Сгенерированные Dart-файлы хранятся в Git.
4. Использовать `context.l10n.messageName` в виджете. В асинхронном обработчике
   получить `final strings = context.l10n` перед первым `await`.

## Добавить язык

1. Создать `app_<код>.arb` с переводом всех сообщений шаблона.
2. Добавить родное название языка в `appLanguageNames` в `l10n.dart`.
3. Выполнить `flutter gen-l10n`: делегаты, список поддерживаемых языков и
   переключатель настроек подхватят новый язык. Не добавлять код языка в провайдер.
4. Проверить `flutter analyze` и `flutter test`, включая формы и длинные тексты
   на узком экране. Проверка каталогов в `localization_test.dart` сравнивает ru/en;
   при добавлении языка расширить её на новый каталог.

## Неизменяемые описания настроек

Схемы protobuf-настроек и модели остаются независимыми от Flutter и хранят исходные
подписи. На границе отображения `context.builtIn` переводит только известные
подписи, справку и сообщения ошибок через тот же ARB-каталог. Поле метаданных
`x-source` содержит исходную подпись; `x-localize-args` отмечает параметры, которые
сами являются встроенными текстами, а не пользовательскими данными.

После изменения таких метаданных выполнить:

```sh
python3 tool/gen_label_localizations.py
flutter gen-l10n
dart format lib/l10n/built_in_text.dart
```

`built_in_text.dart` генерируется этим скриптом; остальные Dart-файлы каталога —
Flutter. Исходная подпись и `x-source` должны совпадать. Новые обычные виджеты
используют типизированные обращения к `AppLocalizations` без адаптера.

Не передавать в `builtIn` сообщения чатов, имена нод, названия каналов, заметки,
пользовательский ввод и тексты объявлений сервера. Они отображаются как пришли.
Технический журнал сохраняет исходные события/ошибки и текст прошивки для
диагностики; подписи его экрана локализованы. Названия протокольных режимов,
моделей плат и команды терминала не переводятся.
